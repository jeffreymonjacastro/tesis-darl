# DARL: PhysioNet A → B

`v1/input/main.ipynb` is a short three-day integration run. `v2/input/main.ipynb`
is the 21-day experiment. Both are generated by `make_notebooks.py`, run on a
Kaggle T4, and attach the processed PhysioNet parquet and private `darl-package`
source dataset. Generated `outputs/` are ignored by Git.

The patient split is stratified by whether a patient ever has `SepsisLabel=1`.
Site A is split 70/15/15 for initial XGBoost training, validation and held-out
test. Site B is split 60/20/20 for DQN learning, checkpoint selection and final
test; each B partition is then divided into disjoint update and evaluation
patients. All observed hours of a patient stay in one partition. Only HR,
O2Sat, Temp, SBP, MAP, DBP and Resp are model inputs. `ICULOS` is retained as
patient-relative time, never as an XGBoost feature.

Each scenario replays the same patient order for a given seed. At most 200 beds
are occupied per simulated hour; when the last observed row for a patient is
used, their bed receives the next unseen patient on the following hour. This
is a replay device, **not** a real admission/discharge history or calendar.
Patients starting with `ICULOS>1` have unobserved earlier histories. The last
row is not evidence of clinical discharge. A record is predicted from its own
observed vitals; maintenance decisions are made once a simulated day ends.

The decision at the end of day `d` sees vital measurements through `d` and
labels through `d−1`; its effect begins on `d+1`. The corresponding reward
enters DQN replay only after the `d+1` labels become available. Reward is the
next-day held-out evaluation AUPRC gain against A1 on the same patients minus
`0.25 × normalized_action_cost`. An evaluation day without positives has no
defined AUPRC gain, so the gain is zero and cost remains. A2 fits a median-IQR
correction with the model unchanged. A3 refits only XGBoost; A4 refits both
preprocessing and XGBoost. A3/A4 use inverse-observed-stay patient weights.

Four separate scenarios are compared: clean B, a gradual measurement shift,
a patient-coherent shift of the synthetic label onset, and their combination.
The injection begins on day 8 and reaches its specified maximum by day 14.
The label shift is a statistical stress test, **not** a clinical intervention
or claim about sepsis biology. It is constructed using future labels only in
the offline scenario generator; the agent receives those labels solely after
the stipulated delay.

`final_metrics.csv` compares DQN with permanent A1, permanent A4, random and
a fixed drift-threshold policy on the same B-test seeds/scenarios. It reports
hourly and equal-patient metrics, PhysioNet-style utility on the observed
segments, return, drift detection, update count, time and peak traced Python
memory. The utility is not an official Challenge score because observed
segments can start after admission or end before discharge. `actions.csv`
contains requested and executed actions and any fallback reason. DQN uses the
course-style two-layer 128-unit network, FIFO replay, epsilon-greedy choice,
Adam, hard target copy every 200 updates and CUDA when Kaggle supplies T4.

Rebuild notebooks locally with `python kaggle/darl_dqn/make_notebooks.py`. A
private Kaggle code dataset must be published from the current `code/src/darl`
tree before a kernel push. The metadata in each `input/` lists both dataset
sources. The remote kernel status and `outputs/run_summary.json` must both
indicate completion before interpreting `v2` metrics.

`outputs/figures/` contains six 16:9 PNG/SVG pairs ready for slides: ICU
occupancy and turnover, bed-level patient rotation, synthetic-drift calendar,
AUPRC by policy, cumulative reward, and executed DQN actions. Do not use the v1 occupancy chart as a final
200-bed result: v1 is only an integration check; the final visualization is
generated from v2's all-bed hourly predictions.

## Primera ejecución completa (Kaggle, 2026-09-22)

La versión 3 del kernel `jeffreymonjacastro/darl-physionet-a-to-b-v2`
terminó en `COMPLETE`. `run_summary.json` confirmó 21 días, 200 camas,
cinco semillas (42–46), 100 evaluaciones finales y 219 actualizaciones del
DQN. En B-test, el DQN eligió A1 en todos los días evaluables y obtuvo la
misma AUPRC media que A1 permanente: 0,0254 sin inyección y 0,0297 en el
escenario combinado. A4 permanente empeoró AUPRC y retorno. El detector
preliminar no distinguió bien el drift: no marcó el cambio de medición y dio
alertas por etiquetas incluso en B sin inyección. Por tanto, esta corrida
valida la infraestructura experimental, **no** demuestra una mejora de DARL
ni una detección fiable del drift. No se deben reajustar umbrales mirando
B-test; cualquier calibración posterior debe hacerse en B-train/validation y
repetir una prueba final reservada.
